# Оптимизация ПСП HBM2: Отключение ECC на NVIDIA Tesla V100 32GB

- **Целевой хост**: `192.168.50.101`
- **GPU**: NVIDIA Tesla V100-PCIE-32GB (GV100GL, sm_70)
- **Драйвер / CUDA**: 550.163.01 / CUDA 12.4
- **Дата применения**: 13 октября 2026 г.

---

## 1. Архитектурные предпосылки и цели

На серверных ускорителях Tesla V100 с памятью HBM2 аппаратный механизм коррекции ошибок (ECC, алгоритм SECDED) включен по умолчанию.

### Почему ECC снижает скорость инференса:
1. **Накладные расходы шины памяти**:
   - Контроллер памяти вынужден передавать дополнительные биты синдрома на каждую транзакцию (тратится порядка 10–12% полезной полосы пропускания).
   - Возникают дополнительные задержки (latency tax) на проверку и генерацию контрольных сумм в контроллере HBM2.
2. **Характер нагрузки LLM (Token Generation)**:
   - В фазе авторегрессионной генерации токенов видеокарта прокачивает через шину все веса модели (например, 16–19 ГБ для квантованной модели 27B) на **каждый генерируемый токен**.
   - Эта фаза является классической **Memory Bandwidth Bound** задачей. Любое ограничение ПСП напрямую пропорционально снижает итоговую скорость генерации (tok/s).
3. **Потери полезного объема VRAM**:
   - При активном ECC часть адресного пространства резервируется под служебные структуры контроллера памяти.
   - Отключение ECC высвобождает дополнительную VRAM (порядка 600–800 МБ чистой памяти при полной аллокации модели), снижая риск OOM на длинных контекстах (112K–128K).

## 2. Результаты применения на хосте 192.168.50.101

### Сравнение состояния подсистемы памяти:

| Параметр | До оптимизации (ECC ON) | После оптимизации (ECC OFF) | Эффект |
|---|:---:|:---:|:---:|
| **Текущий режим ECC (`ecc.mode.current`)** | `Enabled` | `Disabled` | Отключен аппаратный оверхед |
| **Ожидаемый режим ECC (`ecc.mode.pending`)** | `Enabled` | `Disabled` | Зафиксировано в энергонезависимой памяти |
| **Общая память FB Memory** | 32 768 MiB | 32 768 MiB | — |
| **Свободная VRAM при загруженной модели** | **83 MiB** | **759 MiB** | **+676 MiB свободного запаса VRAM** |
| **Штраф латентности шины HBM2** | ~10–12% | 0% | Полная пропускная способность шины HBM2 |

### Дополнительные системные эффекты:
- **Энергонезависимость**: Состояние флага ECC хранится в EEPROM/NVRAM самой карты Tesla V100. Настройка сохраняется после любых последующих перезагрузок без необходимости добавления в cron или systemd.
- **Сохранение сервисов**: Все фоновые сервисы хоста (`qwen38-llama-server`, `omniroute`, `deepseek-harness`, `v100-fancontrol`, `nvidia-power-boot`) корректно перезапустились и функционируют в штатном режиме.

## 3. Регламент управления ECC

### Проверка текущего статуса:
```bash
nvidia-smi --query-gpu=index,name,ecc.mode.current,ecc.mode.pending,memory.total,memory.free --format=csv
```

### Отключение ECC:
```bash
# 1. Перевести флаг в Disabled
sudo nvidia-smi -i 0 -e 0

# 2. Выполнить перезагрузку для переинициализации контроллера памяти HBM2
sudo reboot
```

### Включение ECC (при необходимости возврата):
```bash
sudo nvidia-smi -i 0 -e 1
sudo reboot
```

## 4. Синергия с профилями питания и тактовых частот хоста

На хосте `192.168.50.101` развернут сервис расписания питания и частот `/usr/local/bin/nvidia-power-scheduler.sh`:

### Режимы работы:
1. **Дневной режим (`day`, 09:00 — 23:00 MSK)**:
   - **Power Limit**: `160W` (сбалансированный профиль высокой производительности).
   - **Фиксация частоты ядра (Clock Lock)**: `1380 МГц` (`nvidia-smi -lgc 1380` — максимальная поддерживаемая частота GPU).
   - **Эффект**: Устраняет задержки DVFS (переключения P-state между шагами декодирования), обеспечивает стабильную латентность и максимальный tok/s при активной генерации.
2. **Ночной режим (`night`, 23:00 — 09:00 MSK)**:
   - **Power Limit**: `100W` (холодный бесшумный профиль).
   - **Частоты ядра (Auto DVFS)**: сброс фиксации (`nvidia-smi -rgc`).
   - **Эффект**: Драйвер автоматически опускает частоты в простое (до 945–1230 МГц), снижая нагрев кристалла и обороты системы охлаждения в ночное время.
3. **Автоматический выбор при старте (`auto`)**:
   - `nvidia-power-boot.service` при загрузке ОС определяет текущий час (MSK) и мгновенно активирует дневной или ночной профиль.

### Управление расписанием через systemd:
- `nvidia-power-day.timer` — срабатывает ежедневно в `09:00 MSK` (`nvidia-power-day.service`).
- `nvidia-power-night.timer` — срабатывает ежедневно в `23:00 MSK` (`nvidia-power-night.service`).
- Ручной вызов:
  ```bash
  /usr/local/bin/nvidia-power-scheduler.sh day     # 160W + Clock Lock 1380 MHz
  /usr/local/bin/nvidia-power-scheduler.sh night   # 100W + Auto Clocks (rgc)
  /usr/local/bin/nvidia-power-scheduler.sh auto    # Выбор по текущему времени
  /usr/local/bin/nvidia-power-scheduler.sh status  # Проверка параметров
  ```

В сочетании с отключенным ECC шина памяти HBM2 работает на максимальной пропускной способности, а зафиксированная днем частота 1380 МГц устраняет просадки при спекулятивном декодировании и пакетной верификации токенов.
